Homework 3
RGB to Grayscale Image Conversion and Post Place and Route Demonstration
Design a system that converts a 128 × 128 RGB image to a grayscale image. Verify the complete design in RTL 
simulation, then synthesize, place and route, verify the implemented design, and display the processed output 
on a monitor.
Project Overview
• Store data: Store the pixel values of the input RGB image in memory.
• Process the image: Convert the RGB pixels to grayscale using Verilog, then synthesize and place and route 
the design.
• Display the result: Display the processed grayscale image.
Detailed Description
1 Prepare the image and software reference
Use MATLAB or Python to obtain the pixel matrix of a 128 × 128 color image and the desired grayscale output 
matrix. Use origImageData or img2mat.py as applicable. The software outputs are for verification; the 
hardware output must be generated by your Verilog design.
The provided MATLAB function imageRGB2BW() takes imageFile, the location of the source image, and returns 
origImageData (the source image matrix) and newImageData (the grayscale image matrix).
The provided Python function color2bw takes imageFile and returns output_mat, the grayscale image matrix.
2 Implement RGB to grayscale conversion in Verilog
Each RGB pixel contains red, green, and blue components. Calculate the grayscale value using the following 
weighted sum:
Grayscale = 0.21 × Red + 0.71 × Green + 0.07 × Blue
Implement the coefficient multiplications using the closest practical fixed-point values. Explain the coefficients, 
arithmetic widths, rounding or truncation, and overflow handling used in your design.
For an RGB representation of the grayscale output, assign the calculated grayscale value to all three channels:
new_pixel(i,j).red = grayscale(i,j);
new_pixel(i,j).green = grayscale(i,j);
new_pixel(i,j).blue = grayscale(i,j);
Phase 1 Deliverables
Submit a complete design verified in RTL simulation. First verify the RGB-to-grayscale conversion
(Combinational Logic) Module with a simple testbench. Then verify the complete system, including 
memories and the state machine. Every design module must be accompanied by a testbench and verified.
1 Software RGB to grayscale conversion
Implement the conversion in MATLAB or Python. Include the input RGB image and the output grayscale image.
2 Fixed point software implementation
Implement a fixed-point version of the conversion in MATLAB or Python. Use this version as the reference for 
evaluating your Verilog hardware implementation. The software reference must use the same coefficient 
approximations, arithmetic widths, rounding or truncation, and overflow rules as the hardware.
3 Detailed design block diagram
Show the conversion module, input and output memories, state machine, counters, and their connections. 
Clearly label the signals and their widths. Include an finite state machine (FSM) diagram and explain the 
loading, processing, and output readback operations.
4 RTL Verilog design files
Include the RGB-to-grayscale conversion module (RGB_BW.v), all memory, state machine, and supporting 
modules, and the top-level module (Top.v) connecting the complete system.
5 Verification testbenches and waveforms
Include testbenches and simulation waveforms for the conversion module and the complete top-level design. 
Verify each module and the integrated system. The top-level testbench must load, process, and read back all 
16,384 pixels. Account for memory and processing latency so that output pixels are stored at the correct 
addresses. These testbenches will also be used for Phase 2 and Phase 3 verification.
6 Software and hardware output comparison
Include the software reference output and Verilog simulation output files. Compare all pixel values and report 
the number of mismatches. Show the original RGB image and the grayscale image reconstructed from the 
Verilog output in your report. A grayscale image generated only by software does not verify the hardware.
7 Verification with another image
Repeat the complete verification using a different 128 × 128 image. Include the input image, software and 
hardware output files, comparison results, and reconstructed grayscale image. Your design will also be graded 
using a different image.
8. Explain in the class how many cells and logic potential the RGB_BW and the top will generate 
Phase 2 Deliverables
Synthesize your verified RTL design and verify the resulting gate-level netlist using the Phase 1 testbenches.
1. Synthesis files: Include the synthesis scripts, constraints, synthesized netlist, and files needed to reproduce 
your synthesis results.
2. Synthesis reports: Include timing, area, and power reports generated by the tools. State the clock constraint 
and report any timing violations or unresolved warnings.
3. Post-synthesis verification: Run the testbenches on the synthesized design. Include simulation waveforms 
and compare all grayscale output pixels with the fixed-point software reference for both Phase 1 images. 
Report the number of mismatches.
4. Report and functional status: Explain your synthesis results and clearly state whether post-synthesis 
simulation is functional. Identify any incomplete or failing components.
Phase 3 Deliverables
Complete place and route, verify the implemented design, and demonstrate the processed grayscale output.
1. Place and route files: Include the implementation scripts, constraints, final design database, post-place-androute netlist, timing annotation file, and final GDSII file.
2. Layout and implementation reports: Include layout screenshots and the timing, area, power, and physical 
verification reports generated by the tools. Identify any timing violations or remaining design rule violations.
3. Post-place-and-route verification: Run the testbenches on the implemented design with back-annotated 
timing. Include waveforms and compare all output pixels with the fixed-point software reference for both 
images. Report the number of mismatches.
4. Image demonstration: Display the grayscale image reconstructed from the post-place-and-route simulation 
output. Include the original RGB image, processed image, and a recorded video explaining your setup and 
results. A major portion of the grade is based on a successful demonstration.
5. Report and functional status: Explain the final implementation and clearly state whether post-place-androute verification and the demonstration are functional. Identify any incomplete or failing components.
Report and Submission Requirements
For each phase, submit a Word or PDF report with detailed block diagrams and a clear statement at the top
